# WordToHtml

把「类 md 字符串」编译成 **A4 分页预览** 与 **Word 可编辑的 docx**，并按 Word 的样式名把 docx 读回来。
也可以在 A4 版面上**直接编辑**（所见即所得），编辑结果同样落到模型、再导出 docx。
页面宽度足够时**两页并排**，不够自动回到一页一排；样式与页边距绑成两套「文件模板」整体切换。

面向中文正式公文（情况说明、报告、立场文件）这一「特定模式」：字体、字号、行距、段距、
标题编号规则全部按固定规格表来，规格表是数据，可以整表覆盖，没有一处硬编码。

| P2 | A4 分页预览（自研分页器 + 页码 + 分节重编号 + 页面宽度足够时双页并排） | ✅ 已验收（页数与 Word 一致，两套文件模板各验一遍） |

| P4 | docx 反向导入（按样式名匹配） | ⬜ 未开始 |

## 快速开始

```bash
npm install
npm run dev        # 打开 demo：左侧写源码，右侧即时出 A4 版面，右上角导出 docx
npm run verify     # 跑完整验收（类型检查 + 库产物 + Word 对账 + 分页单测 + 浏览器实测 + 页数比对）
```

## 组件用法

对外就一个组件：`WtpEditor`（`src/components/WtpEditor.vue`，库里以 named export 导出）。
**顶栏 + 功能区 + 纸张**整副外壳都在它里面 —— 批注侧栏、查找替换面板、插入表格面板、导航窗格、提示条
也归它管。「类 md 源码」pane 与「所见即所得 / 源码」模式切换**不在**组件里（那是 demo 的事，
见下面「插槽」）。

props：

| prop | 类型 | 说明 |
| --- | --- | --- |
| `content` | `string` | 类 md 内容。**它是初始内容**：编辑过程中组件不回写（免得一个字回调一次）。留空 = 空字符串 |
| `fileName` | `string`（必填） | 顶栏那一行的文件名。导出 docx 的名字 = 它 + `.docx`（空名兜底「未命名」，已带 `.docx` 不叠） |
| `author` | `string`（必填） | 修订与批注的作者名 |
| `template` | `string` | 文件模板 key（`DOC_TEMPLATES` 里的一项）；留空 = 第一套 |
| `shortcuts` | `ShortcutOverrides` | 偏好快捷键表，只写要改的动作（见「快捷键」）；留空 = `src/lib/edit/shortcuts.json` 那份默认表 |
| `editable` | `boolean` | 打开编辑层，默认 `true`。**这一项是 W8 加的**（issue 的清单里没有）：组件总得有个办法表达「只读预览」，demo 的源码视图靠它 |

emits：

| 事件 | 载荷 | 说明 |
| --- | --- | --- |
| `save_md` | `string` | 顶栏「保存」按钮或 `ctrl+S`：回传 `toMd(getModel())`。`ctrl+S` 会 `preventDefault`，不弹浏览器自己的保存对话框 |
| `save_docx` | — | 「导出 docx」**真的触发了浏览器下载**之后发出（下载名按上面 `fileName` 的规则算） |
| `update:fileName` / `update:author` / `update:template` | `string` | 受控回写：顶栏文件名、修订作者、文件模板改动时回传。**不接也能用**，只是使用方拿不到新值 |
| `paginated` | `number` | 分页完成后的页数 |
| `toast` | `string` | 一句话提示（组件自己也画提示条，这个事件只是把它报出去） |
| `editor-flags` | `EditorFlags` | 模型里 `::editor` 解析出来的两个开关（载入 / 重建后发一次） |

两个插槽（demo 就靠它们把源码 pane 与模式切换挂回同一副外壳）：

- `#bar-extra`：顶栏里、文件名之后；
- 默认插槽：纸张左侧、导航窗格之后。

最小示例：

```vue
<script setup lang="ts">
import { ref } from 'vue'
import { WtpEditor } from 'wordtohtml'
import 'wordtohtml/dist-lib/wordtohtml.css'

const editor = ref<InstanceType<typeof WtpEditor> | null>(null)
const fileName = ref('关于××的情况说明')
const author = ref('张三')

function onSaveMd(md: string) {
  // 存盘或交给后端；要「随时拿最新 md」也可以直接调 editor.value?.toMd()
  console.log(md)
}
</script>

<template>
  <WtpEditor
    ref="editor"
    content="# 关于××的情况说明&#10;&#10;正文……"
    :file-name="fileName"
    :author="author"
    @save_md="onSaveMd"
    @save_docx="() => console.log('docx 已开始下载')"
    @update:file-name="fileName = $event"
    @update:author="author = $event"
  />
</template>
```

三个必知的点：

- **`content` 是初始内容**，编辑过程中不回写；要拿最新 md 调组件暴露的 `toMd()`（或 `getModel()`），
  `save_md` 交出去的就是同一个字符串；
- **`ctrl+S` 归组件管**：按它就等于点「保存」，并且拦住浏览器默认的「保存网页」；
- 组件自带整屏高度（`height: 100vh`）与内部滚动；要嵌在别处就在外面覆盖 `height`。

demo（`src/App.vue`）本身就是一份接法示例，另外用 URL 开关演示这几个入口（验收脚本也走它们）：
`?shortcuts=bold:ctrl+shift+b,formatAmount:ctrl+alt+4` 覆盖快捷键表、`?template=govDoc` 直接把模板当 prop
递进去、`?empty=1` 演示 `content` 留空。demo 把组件回传的值（`update:*`、`save_md` 收到的 md）与
`save_docx` 的次数攒在 `window.__wtpDemo` 上（`{ fileName, author, template, lastSaveMd, docxCount }`）——
浏览器脚本/控制台可以从那里读；真实使用方直接绑自己的状态即可，不必这么写。

组件暴露的方法（`defineExpose`）—— 前六个是「够用」的那一层，后面是把纸张组件的既有能力转发出来：

| 方法 | 说明 |
| --- | --- |
| `getModel()` / `toMd()` | 取当前模型 / 当前 md（`toMd()` = `save_md` 交出去的那个字符串） |
| `pageCount()` | 当前页数 |
| `exportDocx(): Promise<Blob>` / `downloadDocx(name?)` | 取 docx 二进制 / 直接触发浏览器下载（`name` 省略时走 `fileName` 的规则） |
| `getPaper()` | 底层的 `WordPaper` 实例 —— 开发期钩子（demo 的 `window.__wtpPaper`）与「还没转发到的能力」都走它 |
| `repaginate()` / `getSpec()` / `getMeasurements()` | 重量测分页 / 取生效规格 / 取最近一次量测值（排错用） |
| `focusBlock(blockId)` | 把某块滚到可视区中间（导航窗格点击用它） |
| `undo()` / `redo()` / `canUndo()` / `canRedo()` | 撤销重做 |
| `setEditorFlags({ trackChanges, nav })` | 把编辑器开关写回模型（见 `editor-flags`） |
| `setBlockKind(kind)` / `toggleBold()` / `toggleUnderline()` / `setColor(hex\|null)` / `formatSelectionAsAmount()` | 段落样式与行内格式（金额格式化同 `alt+4`） |
| `insertSpecialSpace(kind)` / `insertPageBreak()` / `insertSectionBreak()` / `insertTable(rows?, cols?)` | 插入类操作 |
| `getSelectionScope()` / `setSearch(q, opts?)` / `nextMatch()` / `prevMatch()` / `replaceCurrent(t)` / `replaceAll(t)` / `clearSearch()` | 查找替换 |
| `addCommentOnSelection(text)` / `addCommentAt(...)` / `replyComment(id, text)` / `removeComment(id)` / `focusComment(id)` | 批注 |
| `getCellSelection()` / `clearCellSelection()` | 整格复选的只读镜像与收起 |

#### 内部组件 `WordPaper`（高级用法）

`WtpEditor` 内部用的是 `WordPaper`（`src/components/WordPaper.vue`，库里也一起导出）：
它只管**纸张**（分页预览 + 编辑层 + 批注侧栏），没有顶栏、功能区与那些浮层。
要把纸张嵌进自己的界面、自己画工具栏时才直接用它 —— 下面这套接口**属于内部组件**，
正常用法不必碰。

`defineExpose` 暴露：

| 方法 | 说明 |
| --- | --- |
| `repaginate()` | 强制重新量测与分页（一般不需要手动调） |
| `exportDocx(): Promise<Blob>` | 取 docx 二进制 |
| `downloadDocx(name?)` | 直接触发浏览器下载 |
| `getModel()` / `getSpec()` | 取当前模型／生效规格 |
| `getMeasurements()` | 取最近一次分页用到的量测值（行数、行高、段距），排错用 |
| `pageCount()` | 当前页数 |
| `setBlockKind(kind)` | 把选中的段落换成某个样式（标题／正文／抬头……） |
| `toggleBold()` / `toggleUnderline()` / `setColor(hex\|null)` | 给选中的文字加粗／加下划线／改色（`null` 恢复默认色）；两个 toggle 都是「全加粗就取消」的切换语义 |
| `formatSelectionAsAmount()` | 把选中的数字改写成千分位 + 两位小数（`alt+4` 调的就是它）；不是合法数字／未选中／跨段时返回 `false` 且不改模型 |
| `resolveRevisions(action)` | 接受／拒绝选区里的修订（`action` 为 `'accept'` / `'reject'`）；没选中文字时按插入符所在的那一串修订算，一处修订都没覆盖到则原样不动（也不记撤销） |
| `insertSpecialSpace(kind)` | 在插入符处插入特殊空格，`kind` 为 `'em'`（U+2003）／`'en'`（U+2002）／`'quarterEm'`（U+2005）；有选区时替换选区，取不到落点返回 `false` |
| `insertTable()` | 在当前段落之后（落点在格子里就插到那张表之后，取不到落点则追加到文末）插入一张空表，返回新表 id；默认 3 列 × 2 个 body 行、`minLines=2`、禁止跨页断行，插入后插入符落在第一个格子开头 |
| `insertTableRow(where)` / `removeTableRow()` | 在光标所在行的上方或下方（`where` 为 `'above'` / `'below'`）插入一行 / 删除光标所在行（光标不在正文行、或正文行只剩一行时空转） |
| `insertTableColumn(where)` / `removeTableColumn()` | 在光标所在列的左侧或右侧（`where` 为 `'left'` / `'right'`）插入一列 / 删除光标所在列（只剩一列时空转；unit/note 行整行一格，列操作不动它们） |
| `setTableMinLines(n)` / `setTableRoleRow(role, on)` | 行高两档（`1` / `2`＝最小一行 / 最小两行，**只管正文行**：表头行与附注行恒一行）；增删表头行（`role='unit'`）或附注行（`role='note'`），各至多一行 |
| `getCellSelection()` / `clearCellSelection()` | 整格复选的只读镜像（`{ tableId, cells }`，模型坐标；没有复选时 `null`）与「收起复选」；复选本身是组件的交互状态，不进模型（拖动刷选 / Ctrl+点击的交互见「表格编辑交互」） |
| `addCommentOnSelection(text)` | 给选中的文字加一条批注 |
| `addCommentAt(blockId, from, to, text)` | 按模型坐标加批注 |
| `replyComment(parentId, text)` / `removeComment(id)` | 回复／删除批注 |
| `undo()` / `redo()` / `canUndo()` / `canRedo()` | 撤销栈（组件自己维护，不用浏览器原生撤销） |
| `focusComment(id)` | 高亮并滚动到某条批注的正文锚点 |
| `getSelectionScope()` | 当前选区覆盖到的模型坐标区间（`SearchScope[]`）；面板打开的那一刻调用它，因为焦点一进输入框实时选区就没了 |
| `setSearch(query, opts?)` | 跑一次查找并存下会话（`opts.regex`／`opts.scope`）；非法正则只通过 `search-state` 事件回 `error`，不抛异常 |
| `nextMatch()` / `prevMatch()` | 移动「当前匹配」并把它滚到可视区中间 |
| `replaceCurrent(text)` / `replaceAll(text)` | 替换当前一处／全部；修订模式下按 Word 语义留痕（见下文） |
| `clearSearch()` | 清高亮与整个查找会话（切到只读时组件自己也会清） |
| `focusBlock(blockId)` | 把某块滚到可视区中间；可编辑时再把插入符放到该块自动编号之后（导航窗格点击用它） |
| `setEditorFlags({ trackChanges, nav })` | 把编辑器开关写回模型（缺省值删字段），见下面 `editor-flags` 事件那一节 |

`WordPaper` 自己的 props：`source`（类 md 源码）、`model`（直接给模型，优先于 source）、`spec`（规格覆盖）、`author`（修订与批注作者名）、
`editable`（打开编辑层）、`trackChanges`（修订模式）、`shortcuts`（自定义快捷键表，见「快捷键」一节）。
事件：`paginated`（分页完成后给出页数）、`selection-change`（选区变化时给出当前段落样式、加粗／下划线／颜色，
以及「选区里有没有修订」—— 工具栏用它回显）、
`toggle-track-changes`（按了 `ctrl+shift+E`，请调用方翻转自己持有的 `trackChanges`）、
`toast`（一句无效输入提示，它自己不做提示 UI，由调用方决定怎么显示）、
`editor-flags`（**模型载入 / 重建之后**给出 md 里 `::editor` 解析出来的两个开关，已补齐默认值；调用方据此设自己的状态）。
`editor-flags` 是单向的：用户在调用方那侧改开关时，要调 `setEditorFlags({ trackChanges, nav })` 把值**写回模型**
（否则切源码视图 / 序列化出来的 md 带不上这一行）。它不会因为 `setEditorFlags` 反过来再发一次事件
—— 那会形成回环，把用户刚改的值覆盖回旧的。`WtpEditor` 就是照这套接线把顶栏那两个开关管起来的。

文档含批注时，纸张右侧自动出现审阅侧栏（锚定文字 + 作者 + 时间 + 内容 + 回复），点条目会在正文里
高亮对应锚点并滚动过去；没有批注时侧栏不占位。

## 文件模板与双页并排

**文件模板**（`DOC_TEMPLATES`）把**样式与页边距绑成一体** —— 公文体例里页边距本身就是格式的一部分，
让人分别选「样式」和「页边距」只会拼出既不是甲模板也不是乙模板的东西。demo 顶栏的那个下拉就是它：

| key | 名称 | 样式 | 页边距 |
| --- | --- | --- | --- |
| `manager` | 管理人文件 | 规格表默认那套 | 四边 25mm |
| `govDoc` | 简易公文格式 | **同一套**（用户已定：两套只差页边距） | 上 37 / 下 35 / 左 28 / 右 26 mm |

模板的类型是「整份 spec 的 `DeepPartial`」而不是「只有页边距」，所以将来真要给第二套不同的字体字号，
往 `spec.styles` 里加就行，预览 CSS 与 docx 样式都从 `resolveSpec(template.spec)` 派生，不用改结构。
`MARGIN_PRESETS` 仍保留（它是已发布的 lib 接口），但已改为**由 `DOC_TEMPLATES` 派生**，不另存一份边距字面量。

切模板时组件会**清掉量测缓存并整篇重量**（`clearMeasureCache` → `refreshLayout({ force: true })`）：
页边距一变版心就变，`render/measure.ts` 里所有行数与行高全部失效，不清缓存就会拿旧版心的量测值算页码。
重量期间插入符与选区按「块 id + 字符偏移」还回去，不会丢。

**双页并排**是自适应的：页带是 `flex-wrap` 横排（`lib/render/css.ts` 的 `.{ns}-pages`），容器够宽两页一排、
不够自动回落成一页一排；`.{ns}-page` 是 `flex: none`，宁可让外层横向滚动也不压窄纸宽 ——
纸一窄版心就变，实测行盒与分页算术会立刻脱节。页间那枚换页标记自己占满整行（`flex-basis: 100%`），
否则并排时会被挤到两页之间去。打印不受影响：`@media print` 里把页带改回 `display: block`，仍是一页一张纸。

demo 的样本文档长度是刻意留够的：两套模板的版心高差 22mm（≈ 2.5 行），样本又正好跨在分页边界上，
所以切模板一定看得见页数变化（否则「切模板必须整篇重量」这条断言无从观察）。

## 编辑层

`editable` 打开后，`.wtp-content`（分页后的每一页版心）就是一个 contenteditable，
用户写的是类 docx 的版面，不需要接触任何 md 语法。

分工是明确的：**DOM 是手感的真相，模型是导出的真相**。

- 打字、输入法组字、选区、原生剪贴板都留给浏览器，手感是原生的；每次 `input` 再把 DOM 读回模型；
- 结构性操作（回车分段、退格合并、工具栏加粗／下划线／改色、`alt+4` 金额格式、插入特殊空格、加批注）
  直接改模型，再重排渲染 —— 因此界面上改的和导出 docx 用的永远是同一份模型，
  不会出现「界面改了、导出没改」。

**正常输入不得触发重排**（否则每敲一个字就重建 DOM、丢掉插入符）这条约束靠两点落实：

1. 渲染只读 `viewDoc` / `pages` 这两个浅响应式快照，编辑中的模型不参与渲染，
   所以打字不会让 Vue 重新渲染 —— `lib/edit/dom.ts` 的坐标换算和 `render/measure.ts`
   的增量缓存都只是读 DOM，不动 DOM；
2. 每次 `input` 仍然量测一遍（只重量内容变过的那块），只有当分页结果确实变了
   （行数或行边界变了）才更新快照、重建 DOM，再按「块 id + 字符偏移」把插入符放回去。
   分页没变时 DOM 原样不动，插入符天然还在原处。

几个具体的约定：

- **自动编号不是模型内容**。段首的「一、」包在 `contenteditable="false"` 的 `.wtp-num` 里，
  不可编辑也不参与读回；页面上、docx 里都是同一个编号来源（`numbering.ts`）。
- **回车分段**：在落点切开当前段落；若当前是标题类段落，后半段成为正文段
  （公文习惯：标题一行一段，回车后就该写正文）。
- **退格合并**：仅当插入符在段落最前面且没有选区时接管，合并到上一段并删除本段。
- **修订模式**：新增文字标 `w:ins`；删除不真删，把删掉的文字原地补回来标 `w:del`，
  与 Word 开着修订时看到的一致。读回靠「和模型比一遍」求出被改动的区间。
  选中修订文字后可以用「开始」页的**接受修订 / 拒绝修订**收尾：接受插入修订＝去掉标记、文字留下，
  接受删除修订＝连文字一起删掉；拒绝则正好相反。没选中文字时按**插入符所在的那一串**同类修订算
  （连敲几个字会是几个 inline，但它们是同一处修订，点一下就能整段处理）。
  按钮常驻置灰，选区（或插入符那一串）里没有修订时不亮，也不会因为忽隐忽现让工具栏换行。
- **批注**：选中文字后写内容即可；焦点离开正文（点进批注输入框）时靠选区快照记住锚定范围。
- **粘贴**按纯文本处理，换行还原成新段落（不导入外部 HTML 的样式）。
- **顶栏那一行是文件名**（可编辑，看着像标题；原来那句 slogan 已取消）。导出 docx 的名字 = 它 + `.docx`：
  已经写了 `.docx` 后缀就不再叠一个，空着时兜底成 `未命名.docx`（不会导出成光秃秃的 `.docx`）。
  真正决定下载名的是调用方传进 `downloadDocx(name)` 的那个参数 —— demo 只是把它绑到了这个输入框。

### 快捷键

快捷键只在焦点位于 A4 版面（`.wtp-content`）里时生效，且默认都会 `preventDefault`，不触发浏览器默认行为。
**默认表**（`DEFAULT_SHORTCUTS`，九个可配置动作）：

| 动作 | 默认组合键 | 作用 |
| --- | --- | --- |
| `bold` | `ctrl+B` | 切换选中文本的加粗 |
| `underline` | `ctrl+U` | 切换选中文本的下划线（模型里是 `underline`，docx 里是 `<w:u w:val="single"/>`） |
| `trackChanges` | `ctrl+shift+E` | 切换修订模式（组件只 `emit('toggle-track-changes')`，由调用方翻转 `trackChanges`） |
| `find` | `ctrl+F` | 打开查找面板（`emit('open-search', 'find')`，面板由调用方画） |
| `replace` | `ctrl+G` | 同上，焦点落在替换框（`emit('open-search', 'replace')`） |
| `undo` | `ctrl+Z` | 撤销 |
| `redo` | `ctrl+Y` | 重做（`ctrl+shift+Z` 也认，它是 `ctrl+Z` 的兄弟键，见下） |
| `formatAmount` | `alt+4` | 把选中的数字改写成 `#,#00.00` 格式（如 `12345.6` → `12,345.60`）；解析不了就 `emit('toast')` 且不改模型 |
| `repeat` | `F4` | 重复上一步格式操作（见下） |

`Enter`（回车分段，格内 `Shift+Enter` 插软换行）、`Tab` 与方向键（格内跨格移动）以及 `ctrl+P`
（交给浏览器打印）**不是可配置动作**，行为见下文各节。

**默认表落在一个可以直接手改的 json 文件上**：`src/lib/edit/shortcuts.json`。它就是上面那张表的原样映射
（`{ "bold": "Ctrl+B", … }`），是默认值的**唯一真相源** —— 改这个文件，组件「不传 `shortcuts`」时的行为就跟着变；
`npm run dev` 里改完会自动重载。上面那张表是**这份 json 当前内容的镜像**（改 json 时顺手同步这一节）。

它同时就是 `shortcuts` prop 的默认值：**这张表可以整表覆盖** —— 给组件传 `shortcuts`
（`{ bold: 'Ctrl+Shift+B', … }`），只写要改的动作，其余留空即用 json 里的默认。
使用方想换一整套键，把 `src/lib/edit/shortcuts.json` 复制过去改好、整份传给 prop 即可
（`resolveJsonModule` 已开，`import myShortcuts from './my-shortcuts.json'` 直接可传）。
宽容解析：大小写不敏感，`Cmd` / `Meta` / `⌘` / `Win` 一律归一到「修饰键」（= `ctrlKey || metaKey`），
数字键同时比 `event.key` 与 `event.code`（中文输入法或非美式布局下 `alt+4` 的 `key` 可能不是数字）。
两条边界：**未知动作名忽略 + 一句 `console.warn`，绝不悄悄改默认表**（写错成 `bolld` 时 `ctrl+B` 仍要加粗）；
**两个动作绑同一个组合键时按上表顺序先到先得**，后到的那个解绑并 `console.warn`。
`Tab` 与方向键**不在表内** —— 它们是编辑器手感（行／列跨格移动），改了会和浏览器行为打架。
命中判定对修饰键**逐项严格比对**：多按一个 Shift 就不算命中，所以 `ctrl+shift+B` 不再等同 `ctrl+B`
（改成快捷键表之前，那条分支只比 `ctrl` + 字母，`ctrl+shift+B` 会顺带触发加粗）。

demo 页可以用 URL 参数把表递进来（验收脚本用它，真实使用方直接传 prop）：
`/?shortcuts=bold:ctrl+shift+b,formatAmount:ctrl+alt+4`。**注意**：把 `bold` 这类动作改绑走之后，
那个键会落回浏览器的原生行为（Chromium 的 contenteditable 认得 `ctrl+B`／`ctrl+I`／`ctrl+U`），
所以「旧键失效」在**改绑后仍有原生行为**的动作（加粗、下划线）上表现为「不再由本组件接管」，
而不是「按了没反应」；`ctrl+shift+E`、`alt+4` 这类没有原生行为的动作则是彻底失效。

**`F4` 重复上一步**只重复**格式类**操作，范围是定死的：加粗、下划线、颜色、段落样式、格内样式、
逐格水平／垂直对齐、行高两档、表头／附注行开关。删除、并段、插表这类破坏性或结构性的操作**不重复**
（会把撤销栈搞乱）。重放走的是同一个公开方法，作用在**当前落点／选区**（与 Word 的 F4 一样），
因此它自己也会记一步撤销 —— 撤销一下退掉的就是这次重放。没有可重复的操作时空转并给出提示条。

`alt+4` 的解析与格式化是纯函数（`lib/edit/amount.ts` 的 `formatAmount`）：接受可选负号、千分位逗号、
一个小数点，输出固定两位小数（第三位起四舍五入）。刻意不用 `toLocaleString` —— 它按运行环境的 locale
选分组符与小数点，同一段文字在不同机器上会输出不同结果。

### 功能区：开始 / 插入 / 布局 / 表格

工具栏按 Word 的样子拆成**四页标签**（`.ribbon-tabs > .ribbon-tab`）：

| 页 | 内容 |
| --- | --- |
| 开始 | 撤销／重做，加粗／下划线／颜色（只剩「红」与「取消」两枚），接受修订／拒绝修订，样式库 |
| 插入 | 三枚特殊空格并排按钮，表格／分节符／分页符，批注输入框 |
| 布局 | 「节」编辑（纸张方向、页码、关联前节、从 1 开始） |
| 表格 | 表格的上下文操作（增删行列、表头／附注行、行高两档、两组对齐、删除整表） |

四页**常驻**，不照 Word 那样「光标进表格才弹出表格页」：那会让标签条与页内容在切进／切出表格时变宽变窄
（乃至换行），下方版面跟着跳 —— 这正是拆标签页要解决的问题。光标不在格子里时「表格」页给一句提示、
控件全部置灰；「布局」页的控件跟着落点走（没有落点时显示一句提示）。
标签页与页内控件一律 `@mousedown.prevent`：焦点不离开正文，切页与点按钮都不丢插入符与选区。
颜色只留红是因为公文体里红色是「标出待核处」的记号，其余六色与这套排版无关。
打印时标签条与四页外壳一起隐藏。

### 插入特殊空格

「插入」页里三枚并排按钮可以往插入符处插入三种不会被 HTML 折叠的空格：`EM SPACE (U+2003)` 全宽、
`EN SPACE (U+2002)` 半宽、`FOUR-PER-EM SPACE (U+2005)` 四分之一宽。有选区时替换选区，
插入后插入符落在刚插入的空格之后。用按钮而不是下拉，是因为插入是「点一下插一个」的动作：
下拉选完必须复位回占位项才认第二次 `change`，连插两个同宽空格都做不到。
它们进 docx 就是普通文本字符，不需要特殊处理。

### 打印

`ctrl+P` 交给浏览器，但打印样式（`@media print`）会把编辑器外壳（顶栏、功能区标签条与四页外壳、源码 pane、
语法说明、批注侧栏、页间换页标记）全部隐藏，只留下 A4 纸。纸张尺寸取自规格表（`@page` 的 `size`），
`margin` 归 0 —— 纸上的白边由纸张自己的 padding（= 页边距）提供，页盒再留一次就成了双份。
分页靠每张纸自己的 `break-before: page`（第一张除外），所以打印预览里页数、断页位置与版面一致，
既不会被裁掉后面几页，也不会多出空白页。

打印样式分三处：纸自己（含批注侧栏、页间换页标记）的 `.wtp-*` 规则在 `lib/render/css.ts` 注入的那份 CSS 里
（要带 `!important`，SFC 的 scoped 样式加了 `data-v` 属性，特异性更高）；编辑器外壳（顶栏、功能区、导航窗格、
浮动面板、提示条）的规则在 `src/components/WtpEditor.vue` 的 `@media print` 里；demo 那侧（源码 pane 的
`.pane-head` / `.legend` / `textarea`）在 `src/App.vue` 的 `@media print` 里 —— 插槽里的节点带的是使用方的 scope，
组件管不到它们。

### 查找替换与导航窗格

`ctrl+F` / `ctrl+G` 打开的是同一个**浮动小面板**：浮在预览区右上角、拖标题栏可移动（拖不出窗格范围）、
`Esc` 或 `×` 关闭，关闭时把焦点还给版面。两种入口只是让焦点分别落在查找框／替换框。
面板里有查找框、替换框、「第 n / 共 m 处」计数（无命中时「共 0 处」）、上一个／下一个／替换／全部替换、
`使用正则表达式` 复选框（默认不勾）与范围单选（`全文` 默认 / `当前选中的文本`）。
面板位置与开关由 App 持有，匹配与高亮由组件持有。

- **匹配是纯函数**（`lib/edit/search.ts`，可在 node 里单测）：跑在每个块的「可搜索文字」上，
  批注锚点与格式切换都不占字符、不会漏匹配；正则模式用 `new RegExp(query, 'g')`，
  非法正则交给 `validateQuery` 出提示文案，`findMatches` 一律返回 `[]` 而不抛异常。
- **范围**在面板打开的那一刻用 `getSelectionScope()` 捕获（焦点一进输入框，实时选区就没了）。
  匹配必须完整落在某一个区间内，不许跨区间。
- **高亮用 CSS Custom Highlight API**（`lib/render/css.ts` 的 `SEARCH_HIGHLIGHT` / `SEARCH_CURRENT_HIGHLIGHT`），
  一个 DOM 节点都不动，所以查找不会触发重排。一个匹配可能横跨两页（同一块被切开），
  高亮会**按分页片段切成多个子 Range** —— 用「起点在前一页、终点在后一页」的单个 Range
  会把两页之间的换页标记与页脚一并圈进去。浏览器不支持时降级成「没有高亮」，匹配数、跳转、替换照常。
- **替换落到模型**：普通模式真删真插（`replaceRange`），修订模式下是「把旧文字标成 `w:del` + 插入新文字标
  `w:ins`」，与手输一样进撤销栈、一样会导出到 docx。替换结果继承被替换区间内第一个 text 片段的
  加粗／下划线／颜色，不会把一段加粗文字换掉却静默丢格式。
- **导航窗格**挂在编辑器最左侧（固定 `200px`，文档有标题时自动出现、可折叠），条目是 `h1`/`h2`/`h3`
  （`title` 不进，与 Word 的导航窗格一致），显示「自动编号 + 块内纯文字」，按层级缩进；
  点击会把该块滚到可视区中间，可编辑时再把插入符放到自动编号之后。
  大纲取自**渲染快照**（`viewDoc` / `viewNumbering`）、只在指纹（`outlineSignature`）变化时才发事件，
  因此正文打字不会带着左栏重渲染。

已知取舍：

- 撤销栈是组件自己按「一次编辑一步」记的（深度 200），不接浏览器原生撤销，
  因此和系统菜单里的「撤销」不是同一套；
- **跨块删除由模型层接管**（`deleteSpan` / `joinWithNext`，issues/20260915）。原生删除会把相邻的
  片段元素并成一个、把其余的直接删掉，而 Vue 手里还留着那些节点的 vnode，页面就再也补不回来了
  —— 所以「选中跨段落的一段再删」「全选本页再删」「页尾 Delete」「页首 Backspace」「粘贴替换选区」
  一概自己做：段落之间按 Word 语义接起来（**段落标记被删掉，两头并成一段**，中间整段消失），
  只有**表格格子掺在选区里**时才退回「各容器各自删掉选中的文字」（格子的单段落模型表达不了并格）。
  修订模式下不并段，只把覆盖到的文字标成 `w:del` 留在原处；
- **页尾 Delete / 页首 Backspace 现在真的能删到相邻页**：删的是模型里插入符之后／之前那个字
  （它可能在下一页／上一页的片段里），删除后整篇重排、文字按 Word 的样子前移或后退。
  这两个键在原生的 contenteditable 里是**空操作**（每页一个宿主，删除跨不过页边界），所以由模型接管；
- **段落标记也由模型删**：在段尾按 Delete 等于把下一段接上来（`joinWithNext`），与已有的
  「段首 Backspace 合并前一段」对称。下一块是表格或换页标记时不改模型、也不放行给浏览器；
- **软换行目前只在表格单元格内支持**（`:::table` 围栏里的 `{br}`，导出为 `<w:br/>`），
  普通段落是否推广待定；格内 **Enter 不接管**、**Shift+Enter 插软换行**（插入符落到换行之后），
  格首 Backspace 与格尾 Delete 被拦下不让浏览器并格；
- **表格结构操作只在「一张表」内部与「删掉整张表」两件事上**：增删行列、表头行／附注行开关、行高两档
  都落在 `lib/edit/table.ts` 的纯函数上；删整表是工具条最右的显式按钮（`removeTable`，**不二次确认**，
  靠撤销兜底）。增删行列会让 `cellId` 里的行/列下标整体位移，所以操作后的插入符按新下标重算
  —— 旧 id 一律作废；
- **`↑` / `↓` 跨格靠 DOM 量测**（比较插入符与格内首/末字符的 `top`）：判不准就不接管，所以多行格、
  量测退化的场合就是「不跨」；落点也不保留横向位置。这部分**只有推理、没有浏览器实测**；
- **删表后的插入符落点**优先取被删表之前第一个段落的末尾，其次之后第一个段落的开头；两边都没有
  可落点的段落时传 `undefined`，靠 `refreshLayout` 的兜底（这种文档形态没被浏览器实测）；
- **格内换样式会改行高、因此页数可以变**（预期行为）；两组对齐不改行高、不改换行点，因而不改页数；
- **关掉修订模式后在「刚被标成插入修订」的文字后面继续打字**，新字会并进那个 `w:ins` 区间
  （读回时按 DOM 上下文继承格式，浏览器就是把字插进了那个 `<span>` 里）。
  在别的段落里打字不受影响 —— 这是「DOM 是手感的真相」付的代价，没有做逐字 diff；
- 源码视图（类 md）与编辑层之间来回切换会经过一次序列化，修订的作者／时间戳与批注的
  回复关系在那条路上会丢（md 语法里没有这两个位置）——只做展示用，别拿它当存档。
- **查找替换**：替换文字按纯文本处理，**不支持 `$1` 这类反向引用**；**默认大小写敏感**，
  不提供「忽略大小写」开关；正则的零宽匹配（如 `^`、`a*`）不进结果集，只会被跳过去
  —— 否则每一处空匹配都会变成一条「第 n 处」，`全部替换` 也会在每个字符位置插一次。
- **已标记删除（`w:del`）的文字不参与查找与替换**。修订模式下「替换」是「把旧文字标成删除 + 插入新文字」，
  旧文字仍留在模型里；若查找还命中它，对同一处反复替换就会不断叠加插入，跳过才能收敛。
- **导航窗格的大纲取自渲染快照**：刚敲进去、还没触发重排的标题文字，要等下一次分页才会反映到左栏
  （换来的是「正文打字不带着左栏重渲染」）。


## 源码语法

一个非空行就是一段（**行与行不会合并成同一段** —— 公文写作习惯是一行一段，用空行分隔反而要多敲回车）。
空行只起分隔作用，不产出内容。

| 行首标记 | 含义 |
| --- | --- |
| `# 标题` | 文本标题（华文中宋 18pt 加粗居中） |
| `## 标题` | 一级标题，自动编号 `一、` |
| `### 标题` | 二级标题，自动编号 `（一）` |
| `#### 标题` | 三级标题，自动编号 `1、` |
| `@ 抬头` | 抬头（正文但取消首行缩进） |
| `>> 落款` | 落款（正文但右对齐），连续多行成组 |
| `- 条目` | 列表段落（五号 10.5pt，无段前段后） |
| `! 条目` | 列表标题（五号加粗居中） |
| `---`（独占一行） | 分节符：新起一页，页码从 1 重排 |
| `===`（独占一行） | 分页符：只强制换页，页码连续 |
| `:::table … :::` | 表格围栏块，见下 |

文档**最前面**还可以有两行指令（写在正文之前，谁先谁后都行；正文里出现的这两行按普通文字处理）：

| 行首标记 | 含义 |
| --- | --- |
| `::editor …` | 编辑器开关：`trackChanges=on`、`nav=off`。**只写非默认值**（默认 = 修订关、导航开），两个键都是默认值时这一行根本不写 |
| `::section …` | 首节的设置：`numbers=off` / `restart=on` / `orientation=landscape`（同样只写非默认值） |

`::editor` 只是「打开文件时界面上的修订模式与导航窗格该是什么状态」，**不影响 docx**。
它由组件的 `editor-flags` 事件报给调用方，用户在界面上改开关时再用 `setEditorFlags` 写回模型 ——
所以「改开关 → 切到源码视图」看到的 md 里就会多出（或消失）这一行，双向可逆：

```
::editor trackChanges=on
::section numbers=off

# 标题
……
```

### 表格

表格用一段围栏块包起来，首行是 `:::table`（可带 `minLines=1|2`、`cantSplit=yes|no` 两个参数，
只写非默认值：`minLines` 默认 1、`cantSplit` 默认 true），末行是独占一行的 `:::`：

```
:::table minLines=2
> 单位：元
| 项目 | 金额 |
| 甲 | 1,234.00 |
< 注：以上金额不含税
:::
```

- `>` 开头是 **unit 行**（表头行上方的「单位：元」这类文字）、`<` 开头是 **note 行**（表尾附注），
  两者**整行一格**、无边框，分别右对齐／左对齐（附注还顶端对齐）；`|` 开头是 **body 行**。
- 表内每行**按未被转义的 `|` 切格**，所以格子里要有竖线就写 `\|`，要有反斜杠就写 `\\`；
  每格的文字走同一套行内语法（`**加粗**`、`__下划线__`、`{红|…}`、`{+…}`、`{-…}`、`[[…|批注]]`）。
- **行高**两档就是 `minLines`：1 = 最小一行、2 = 最小两行（导出为 `HeightRule.ATLEAST`，
  值 = minLines × **该行各格样式的最大行高**）；它只管**正文行** —— **表头行与附注行恒为「最小一行」**，
  不随这个设置变（两行是整张表的装饰，跟着变高只会白白把表格撑长，见下）；
  `cantSplit` 默认禁止本行跨页断开（Word 的 `w:cantSplit`）。
- 表格总宽固定占满版心宽（页面宽 − 左右页边距），列宽等分、除不尽的余数给最后一列。
- 其它行首（空行等）一律忽略；一张表连一行内容都没有时规范化为「1 行 1 个空 body 格」。
- **格首指令**：一格的内容可以整格包在 `{@<token>[,<token>]…|<格内正文>}` 里，用来逐格换样式与两组对齐
  （unit / note 行也认）。token 三族互不冲突、不认识的 token 一律忽略：样式名（`title`/`h1`/`h2`/`h3`/`body`/
  `salutation`/`signature`/`attachment`/`listTitle`/`listItem`，缺省 `listItem`）、水平（`left`/`center`/`right`，
  只做这三档、不提供两端对齐）、垂直（`top`/`middle`/`bottom`，缺省 `top`）。
  序列化顺序固定 `kind` → `h` → `v`，且只写非默认值 —— 三个都没值的格不写指令，老样本一个字节不变。
  正文里真写 `{@h2|x}` 会被转义成 `\{@h2\|x\}`（反斜杠吃掉 `{`），往返可逆；不合法的形式
  （`{@` 找不到闭合的 `}`、或没有分隔 token 与正文的 `|`）一律当普通内容处理，绝不吞掉后面的内容。
  这一族只在表格解析里认，普通段落里没有这套语义，也不与 `{+ins}` / `{-del}` / `{#RRGGBB|…}` / `{br}` 冲突。
  例：`> {@h2,right|单位：元}`、`| {@h2,center|项目} | {@center|金额} |`、`| {@left,bottom|1,234.00} |`。

表格在预览里按**行**排出来：外层 `<table>` 铺满版心（固定布局、合并边框），格内文字缺省是「列表段落」样式、
换成别的样式时用那条样式自己的字体字号与行距，单元格左右内边距与 docx 侧取同一个数（108 缇 = 5.4pt）。
行高的最小值落在 **`<td>` 的 `height`** 上（表格格的 `height` 语义就是「最小高度」：内容更高照样撑开，
与 docx 侧 `w:trHeight @ATLEAST` 同义）、按该格样式算 —— 一行里各格取各自的值，实际行高天然由最高的那格决定
（docx 侧的 `w:trHeight` 用同一条规则）。**表头行与附注行的下限恒为「一行」**（`minLines=2` 也不变，
见上面那条 md 语法的说明；预览只给 `td.wtp-td-plain` 上「一行」那条规则，带 `-min2` 的规则用
`:not(.wtp-td-plain)` 把它排除在外，导出侧同一处规则）。**不能**把这个下限写在格内那层 div 的 `min-height` 上：
那样 div 自己就被撑成两行高、而字待在 div 顶部，于是 `<td>` 上的 `vertical-align` 挪的是「已经填满格子的
div」，居中／底端一点视觉效果都没有（2026-09-15 修）。分页时表格**行是原子的**：一行放不下就整行挪到
下一页，行内不拆；同一页相邻的同表行合并成一个片段（一页一张 `<table>`），跨页才断开。
demo 的工具栏有「插入表格」按钮：点开是一个浮动规格面板（与查找替换面板同一套做法，可拖、
`×`／`Esc` 关），在里面选**行数**与**列数**再插入，默认 2 行 × 3 列、最小行高两行、禁止跨页断行。
面板里敲进去的数值不设信任：越界会夹到 1–30 行 / 1–12 列，输入框清空则按 1 处理。

**表格编辑交互**（W4b-1）：功能区的**「表格」页**就是原先那条**表格上下文工具条**
（落点提示与全部控件都吃 `selection-change` 事件里的 `selection.table`）。这一页**常驻** ——
光标不在格子里时它显示一句提示、控件全部置灰，而不是整条消失：它原来只在格内出现，切进／切出表格时
工具栏宽度一变就可能换行，下方版面跟着跳（2026-09-15 拆标签页时一并解决）。上面是：
落点提示（`第 N 行第 M 列`，行列都是下标、显示时 +1；表头行／附注行没有列的概念，只显示行名）、
行（`上方插入行`／`下方插入行`／`删除行`）、列（`左侧插入列`／`右侧插入列`／`删除列`）、
行高两档 radio（`最小一行`＝1 / `最小两行`＝2，即 docx 的 `HeightRule.ATLEAST` 倍数）、
以及表头行与附注行的有／无 radio。按钮与 radio 一律 `@mousedown.prevent`，焦点不离开正文，
落点与原生选区才保得住。禁用规则：`删除行` 在光标不在正文行、或正文行只剩一行时禁用；
`删除列` 在只剩一列时禁用。`cellId` 里嵌的是行/列下标（`tb1.r2c1`），任何增删都会让其后的
格子 id 整体位移，所以操作完的插入符是按**新下标**重算后放回去的（偏移再夹到该格当前长度以内）。

**表格收尾**（W4b-2）在「表格」页里又加了**水平**（左／居中／右）与**垂直**（顶端／居中／底端）两组对齐按钮，
以及最右端的**「删除表格」**（**不二次确认**，靠 `pushHistory` 的撤销兜底 —— 与全仓库一致，项目里没有弹窗形态）。
两组对齐都是**逐格**的：给 `TableCellModel.align` 存 `{ h?, v? }`，只存被改过的那一维；
按钮的 active 态吃**已解析默认值**后的实际值（水平：unit 右 / note 左 / body 跟该格样式；垂直一律顶端），
**再点同一个值就是清除覆盖、回默认**。水平只做三档，不提供两端对齐；对齐不改行高、不改换行点，所以**不改页数**。
格内**换样式**走「开始」页里的**样式库**：光标在格内时它作用于**该格**（`TableCellModel.kind`，缺省「列表段落」），
只有那一格的类名从 `wtp-listItem` 变成 `wtp-<kind>`；**换样式会改行高，因此页数可以变**，这是预期行为。

**复选多格**（W7）：表格里可以像 Word 那样**整格**选一片格子，然后一次把操作施加到整批上。

- **拖动刷选**：在格内按下后**先什么都不做**；指针一旦越过**起点格**的盒子，才转成整格刷选
  （此刻把已有的原生选区折叠掉，此后不再让原生选区扩展），选区 = 「起点格 ↔ 当前格」构成的**矩形块**。
  没出格就还是**普通的选文字** —— 这条是硬要求：格内加粗、下划线、加批注全靠它（拖出格边界才变成整格）。
- **Ctrl+点击**（或 Ctrl+拖动）在已有复选上**并**一块矩形：以「上一次的落点（锚格）」为一个端点、
  点中的格为另一个端点。**Ctrl+点击一个已被选中的格 = 把包含它的那一块去掉**（块没了就是空复选）。
- **整格高亮**：命中的 `<td>` 挂一个底色类名（`.wtp-cellsel`），只改底色、**不碰 padding / 高度 / 边框**，
  所以量测与分页完全不受影响；同一张表跨页时，各片段按**模型坐标**各自画（选中态不记在 DOM 元素上）。
- **退出条件**：`Esc`、点正文别处、光标移出那张表、重排后那张表不在页面上（含删表、撤销回到更小的表）——
  一律清空。增删行列与表头／附注行开关会让行列下标整体位移，复选在这几个动作里也一并收起。
- **批量能做的只有**「两组对齐」与「格内样式」：单选时目标列表就一格，多选时是整批（行优先、去重），
  两条路走的是同一条代码；**一次批量只记一步撤销**，`ctrl+Z` 一步退回整批。
  对齐/样式按钮的**选中态按整批的一致性回显** —— 选中的格里对齐（或样式）不一致时，按钮一个都不亮。
  批量对齐不改行高、不改换行点，所以不改页数；批量换样式会改行高，页数可以变。
- 多选时「表格」页的提示换成「已选 N 格」；行高两档、表头／附注行开关、增删行列**照旧可用**，
  仍按**落点那一格**工作（这几件是整表级的，不作用于整批）。
- **明确的省略**：不做 Word 那种「拖到表格外自动扩成整行 / 整列」，也不做不连续块之间的合并显示。

**键盘跨格**：`Tab` / `Shift+Tab` 在格内按**行优先**顺序跨格（unit / note 行整行算一格、渲染时补出来的幻影格跳过）；
**在最后一格按 Tab（或第一格按 Shift+Tab）不作任何响应** —— 不换行、不自动加行、不把焦点跳出正文。
`←` / `→` 只在**格首**（←）或**格尾**（→）跨到上一格末尾 / 下一格开头，格内其它位置仍由浏览器移动光标。
`↑` / `↓` 只在插入符位于该格的**首 / 末视觉行**时跨到上下相邻格（同列；目标是 unit / note 行时列归 0），
判定靠 `getClientRects()` 比较插入符与格内首 / 末字符的 `top`：**判不准就完全不接管**（fail-open），
落点一律是目标格开头、不保留横向位置。跨格只挪原生选区、**不改模型、不重排**（所以插入符不会丢、也不会触发重排）。

格内**可以直接打字**：格子是编辑层里的「伪块」，id 用 `cellId(tableId, r, c)` 挂在格内那层 div 上，
于是坐标换算一行都不用改；加粗／下划线／改色、查找替换、批注也都覆盖格内文字。
**Shift+Enter** 在格内插一枚**软换行**（`{br}`，零宽），插入符落到换行**之后**
（软换行零宽，默认的坐标还原会落到换行之前 —— 那会让回车后敲的字打回上一行）；
格内 **Enter 不接管**（单元格是单段落，分段表达不出来）。**格首 Backspace 与格尾 Delete 会被拦住**：
放给浏览器的话原生会把相邻 `<td>` 的 DOM 并掉，表格结构当场就坏。
格内多行粘贴会把换行变成软换行 `{br}`（同上，单元格是单段落）。

行内标记（可互相嵌套）：

| 写法 | 含义 |
| --- | --- |
| `**文字**` | 加粗 |
| `__文字__` | 下划线（导出为 `<w:u w:val="single"/>`） |
| `{红｜文字}` | 改色，支持中文色名（红黑蓝绿紫橙灰黄白）或 `{#RRGGBB｜文字}` |
| `{+文字}` | 插入修订（导出为 `w:ins`） |
| `{-文字}` | 删除修订（导出为 `w:del`） |
| `[[文字｜批注内容]]` | 批注，锚定在「文字」上 |
| `{br}` | 软换行（Word 的 `<w:br/>`）：零宽、不占字符位 |
| `\` | 转义上述标记字符 |

> 上表里的全角竖线是为了在文档里显示清楚，实际语法用的是**半角 `|`**。

## 样式规格表

规格表在 [`src/lib/spec.ts`](src/lib/spec.ts)，是预览 CSS 与 docx 样式的**唯一来源**，
`resolveSpec(override)` 做逐层合并。默认值：

| 类型 | 字体（中文／西文） | 字号 | 加粗 | 对齐 | 首行缩进 | 行距 | 段前／段后 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 文本标题 | 华文中宋／Times New Roman | 18pt | ✓ | 居中 | — | 26pt 固定值 | 1.5 行／1.5 行 |
| 一~三级标题 | 仿宋／Times New Roman | 14pt | ✓ | 两端 | 2 字符 | 25pt 固定值 | 0.5 行／0.5 行 |
| 正文 | 仿宋／Times New Roman | 14pt | — | 两端 | 2 字符 | 25pt 固定值 | 0.5 行／0.5 行 |
| 抬头 | 仿宋／Times New Roman | 14pt | — | 左 | — | 25pt 固定值 | 0.5 行／0.5 行 |
| 落款 | 仿宋／Times New Roman | 14pt | — | 右 | — | 25pt 固定值 | 0.5 行／0.5 行 |
| 列表标题 | 仿宋／Times New Roman | 10.5pt | ✓ | 居中 | — | 12pt 最小值 | 0／0 |
| 列表段落 | 仿宋／Times New Roman | 10.5pt | — | 两端 | — | 12pt 最小值 | 0／0 |

- 页面默认 A4，四边 25mm（= 「管理人文件」模板的页边距）。文件模板见上一节：`DOC_TEMPLATES` 把样式与
  页边距绑成一体，`MARGIN_PRESETS` 由它派生（四边各自取值）；`page.margin` 也可以直接覆盖。
  页码段落用内置「页脚」样式（居中 9pt）。
- 样式名对照：

| 块 | docx 样式名 | 来源 |
| --- | --- | --- |
| `title` | 标题 | Word 内置（Title） |
| `h1` / `h2` / `h3` | 标题 1 / 标题 2 / 标题 3 | Word 内置（Heading 1-3），自动带上大纲级别 |
| `body` | 正文 | Word 内置（Normal）。正文段落不挂样式，格式定义在默认样式上 |
| `listItem` | 列表段落 | Word 内置（List Paragraph） |
| `footer` | 页脚 | Word 内置（Footer） |
| `salutation` / `signature` / `listTitle` | 抬头 / 落款 / 列表标题 | 自定义（Word 无对应内置） |

- **「内置」的判定依据是 `w:name` 与 Word 的本地化名逐字相等**（含「标题 1」中间那个空格），
  不是 `w:styleId`。所以样式 id 仍保留 `WT-` 前缀 —— 既不影响内置归属，又能避开 `docx` 库的坑：
  styleId 一旦撞上它的内置样式表（`Heading1`、`Title`），它会额外注入一份自己的默认定义，
  同一份 `styles.xml` 里就会出现两个同 id 的 `w:style`。**反向解析按样式名匹配。**
- 命中内置样式后 Word 会自动补上大纲级别，标题因此能出现在导航窗格里，这是改内置名顺带拿到的。

```
src/lib/

  types.ts           文档模型（块 / 行内 / 修订 / 批注）+ 批注锚定文字提取
  numbering.ts       中文序数编号与层级重置
  md/parse.ts        类 md → 模型        md/serialize.ts  模型 → 类 md
  edit/model.ts      编辑操作的纯函数层（切分／合并／替换／格式化／批注／修订）
  edit/dom.ts        预览 DOM ⇄ 模型的桥（读回 inline、插入符与选区的坐标换算）
  edit/amount.ts     金额格式化（千分位 + 两位小数，纯函数，不碰 locale）
  edit/search.ts     查找与替换（纯函数：字面量／正则、范围限定、跳过删除修订、替换留痕）
  edit/outline.ts    导航窗格的大纲（h1/h2/h3 → 条目 + 指纹）
  edit/shortcuts.ts  快捷键表（默认表 + 组合键解析 + 命中判定，纯函数）
  docx/export.ts     模型 → docx（段落样式、页码域、w:ins/w:del、w:u、批注）
  render/css.ts      规格表 → 预览 CSS（含打印样式）
  render/html.ts     行内标记 → HTML（预览、量测、编辑读回共用同一套结构）
  render/measure.ts  DOM 实测：行数、行高、每行起始字符偏移（带增量缓存）
  render/paginate.ts 纯函数分页：装箱 + 跨页按行切开 + 分节重编号
src/components/WtpEditor.vue   对外组件：顶栏 + 功能区 + 纸张（含浮动面板、导航窗格、提示条）+ props/emits
src/components/WordPaper.vue   纸张（预览 + 编辑 + 批注审阅侧栏），内部组件／高级用法
src/App.vue                    demo：WtpEditor + 类 md 源码 pane + 模式切换
scripts/                       验收脚本（见下）
```

分页不是 CSS 断页，而是「实测行盒 → 装箱 → 在行边界切开」算出来的：行距是固定值，
行高因此是确定量，分页可以算出来而不是猜。孤行控制默认开启（页尾与页首各至少 2 行，
因此少于 4 行的段落不会被拆开）。

## 验收方式

## 已知限制

- **字体依赖本机安装**。预览用 `仿宋／华文中宋／Times New Roman`，docx 里写的也是这几个名字。
  这三个都是商业字体，不能内置；换一台没装这些字体的机器，预览会回退到 serif，行宽会变。
- **「段前／段后 N 行」用磅值写死**。`docx` 库没有暴露 Word 的 `w:beforeLines`（按行计的动态段距），
  这里按本段行距换算成固定磅值。视觉等价，但不是随行距联动的动态值。
- **自动编号写成了正文文字**，不是 Word 原生多级列表。好处是预览所见即所得、重新导入能准确还原；
  代价是在 Word 里手动增删标题不会自动重编号（在本组件内会自动重排）。
- **分节符会多出一个空段落**。`docx` 库用一个只带 `w:sectPr` 的空段落承载分节符，
  Word 把它读成含分页符的一段，效果是上一节末尾多一个空行。
- **批注的「已解决」状态需要线程**。`docx` 只在存在 `parentId` 回复时才会写
  `commentsExtended.xml`，因此单条批注标记 `resolved` 不会生效（库的现状，非本项目取舍）。
- 预览里的批注高亮与修订着色是**近似**，不追求与 Word 像素级一致。
- **预览分页与 Word 分页的逐页对齐只验到样本这一级**：`verify:pages` 会逐套模板把预览页数与 Word 页数对账，
  样本上**两套模板现在都对得上**（管理人文件 4 ↔ 4，简易公文格式 5 ↔ 5）。
  样本里加表格（W4a-2）之后曾出现「管理人文件那套预览多一页（5 vs 4）」，W7 的表头 / 附注行恒一行
  修掉了那个偏差（表格短了两行，预览少一页，与 Word 的 4 页吻合）—— 这条不再是遗留问题，
  但它原本就属「表格版式保真」这一类：换字体、混排西文比例很高、或超大表格时，
  两个排版引擎本来也可能出现逐行差异。
- **表格的预览版式没有做过人工核对**（机器断言已经全跑，见「验收方式」）。
  行高最小值靠**`<td>` 的 `height`**（表格格的 `height` 就是最小高度；格内 div 上写 `min-height`
  会把 div 自己撑高、`vertical-align` 就失效了 —— 2026-09-15 修），
  单元格左右内边距与 docx 侧取同一个数（108 缇 = 5.4pt）；另有一处已知偏差：
  列表段落的 CSS `line-height` 是固定 12pt，而 Word 的 `atLeast 12pt` 是「不小于」，
  单行格两者相同（`minLines=2` → 24pt），**多行格**可能差零点几磅。
- **横竖混排的打印只验到规则层**：屏幕上的每页几何（纸宽高、页边距、方向）由行内样式给出、
  可断言；打印时的方向靠命名 `@page`（横排节挂 `wtp-landscape`，纵排节走默认 `@page`）表达，
  而 `verify:*` 能断言到的是 `@page` 规则、每张纸的断页属性、以及**纵排文档真打一份 PDF 的页数**。
  横排/混排真打出来的观感（命名页切换是否留下多余空白纸）仍需人工核对。
- 编辑层还有两处已知缺陷（都记在 `PLAN.md` 第 11 节，**对应断言保持红着**，没做放水处理）：
  **格内 Shift+Enter 之后接着打字会把软换行复制一份**；**「节」工具条只在光标落进正文后才出现**
  （W5 的结论与本文档原先都写作「编辑模式常驻」）。
- **改绑快捷键不会「接管」浏览器的原生编辑键**：把 `bold`／`underline` 改到别的组合键之后，
  原来的 `ctrl+B`／`ctrl+U` 会落回 Chromium 的 contenteditable 原生加粗／下划线 —— 模型的读回机制
  照样会把结果同步进模型（导出不失真），但这一步不再经过本组件的工具栏语义（不会走 `toggleBold`）。
  没有原生行为的动作（`ctrl+shift+E` 修订模式、`alt+4` 金额格式）改绑后则是彻底失效。
