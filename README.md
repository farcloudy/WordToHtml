# WordToHtml

把「类 md 字符串」编译成 **A4 分页预览** 与 **Word 可编辑的 docx**，并按 Word 的样式名把 docx 读回来。
也可以在 A4 版面上**直接编辑**（所见即所得），编辑结果同样落到模型、再导出 docx。
页面宽度足够时**两页并排**，不够自动回到一页一排；样式与页边距绑成两套「文件模板」整体切换。

面向中文正式公文（情况说明、报告、立场文件）这一「特定模式」：字体、字号、行距、段距、
标题编号规则全部按固定规格表来，规格表是数据，可以整表覆盖，没有一处硬编码。

| P4 | docx 反向导入（按样式名匹配） | ⬜ 未开始 |

## 快速开始

```bash
npm install
npm run dev        # 打开 demo：左侧写源码，右侧即时出 A4 版面，右上角导出 docx
npm run verify     # 跑完整验收（类型检查 + Word 对账 + 分页单测 + 浏览器实测 + 页数比对）
```

## 组件用法

```vue
<script setup lang="ts">
import { ref } from 'vue'
import WordPaper from './components/WordPaper.vue'
import { mm } from './lib/spec'
import type { DeepPartial, Spec } from './lib/spec'

const source = ref('# 关于××的情况说明\n\n@ 苏州市公安局：\n\n……')
const paper = ref<InstanceType<typeof WordPaper> | null>(null)

// 任何一项都能覆盖，页边距只是举例
const spec = ref<DeepPartial<Spec>>({
  page: { margin: { top: mm(30), right: mm(25), bottom: mm(30), left: mm(25) } },
})
</script>

<template>
  <WordPaper ref="paper" :source="source" :spec="spec" author="张三" editable @paginated="n => console.log(n)" />
  <button @click="paper?.downloadDocx('情况说明.docx')">导出 docx</button>
  <button @click="paper?.toggleBold()">加粗</button>
</template>
```

`defineExpose` 暴露：

| 方法 | 说明 |
| --- | --- |
| `repaginate()` | 强制重新量测与分页（一般不需要手动调） |
| `exportDocx(): Promise<Blob>` | 取 docx 二进制 |
| `downloadDocx(name?)` | 直接触发浏览器下载 |
| `getModel()` / `getSpec()` | 取当前模型／生效规格 |
| `getMeasurements()` | 取最近一次分页用到的量测值（行数、行高、段距），排错用 |
| `pageCount()` | 当前页数 |
| `setBlockKind(kind)` | 把选中的段落换成某个样式（标题／正文／抬头……） |
| `toggleBold()` / `toggleUnderline()` / `setColor(hex\|null)` | 给选中的文字加粗／加下划线／改色（`null` 恢复默认色）；两个 toggle 都是「全加粗就取消」的切换语义 |
| `formatSelectionAsAmount()` | 把选中的数字改写成千分位 + 两位小数（`alt+4` 调的就是它）；不是合法数字／未选中／跨段时返回 `false` 且不改模型 |
| `insertSpecialSpace(kind)` | 在插入符处插入特殊空格，`kind` 为 `'em'`（U+2003）／`'en'`（U+2002）／`'quarterEm'`（U+2005）；有选区时替换选区，取不到落点返回 `false` |
| `insertTable()` | 在当前段落之后（落点在格子里就插到那张表之后，取不到落点则追加到文末）插入一张空表，返回新表 id；默认 3 列 × 2 个 body 行、`minLines=2`、禁止跨页断行，插入后插入符落在第一个格子开头 |
| `insertTableRow(where)` / `removeTableRow()` | 在光标所在行的上方或下方（`where` 为 `'above'` / `'below'`）插入一行 / 删除光标所在行（光标不在正文行、或正文行只剩一行时空转） |
| `insertTableColumn(where)` / `removeTableColumn()` | 在光标所在列的左侧或右侧（`where` 为 `'left'` / `'right'`）插入一列 / 删除光标所在列（只剩一列时空转；unit/note 行整行一格，列操作不动它们） |
| `setTableMinLines(n)` / `setTableRoleRow(role, on)` | 行高两档（`1` / `2`＝最小一行 / 最小两行）；增删表头行（`role='unit'`）或附注行（`role='note'`），各至多一行 |
| `addCommentOnSelection(text)` | 给选中的文字加一条批注 |
| `addCommentAt(blockId, from, to, text)` | 按模型坐标加批注 |
| `replyComment(parentId, text)` / `removeComment(id)` | 回复／删除批注 |
| `undo()` / `redo()` / `canUndo()` / `canRedo()` | 撤销栈（组件自己维护，不用浏览器原生撤销） |
| `focusComment(id)` | 高亮并滚动到某条批注的正文锚点 |
| `getSelectionScope()` | 当前选区覆盖到的模型坐标区间（`SearchScope[]`）；面板打开的那一刻调用它，因为焦点一进输入框实时选区就没了 |
| `setSearch(query, opts?)` | 跑一次查找并存下会话（`opts.regex`／`opts.scope`）；非法正则只通过 `search-state` 事件回 `error`，不抛异常 |
| `nextMatch()` / `prevMatch()` | 移动「当前匹配」并把它滚到可视区中间 |
| `replaceCurrent(text)` / `replaceAll(text)` | 替换当前一处／全部；修订模式下按 Word 语义留痕（见下文） |
| `clearSearch()` | 清高亮与整个查找会话（切到只读时组件自己也会清） |
| `focusBlock(blockId)` | 把某块滚到可视区中间；可编辑时再把插入符放到该块自动编号之后（导航窗格点击用它） |

props：`source`（类 md 源码）、`model`（直接给模型，优先于 source）、`spec`（规格覆盖）、`author`（修订与批注作者名）、
`editable`（打开编辑层）、`trackChanges`（修订模式）。
事件：`paginated`（分页完成后给出页数）、`selection-change`（选区变化时给出当前段落样式与加粗／颜色状态，工具栏用它回显）、
`toggle-track-changes`（按了 `ctrl+shift+E`，请调用方翻转自己持有的 `trackChanges`）、
`toast`（一句无效输入提示，组件不做提示 UI，由调用方决定怎么显示）。

文档含批注时，组件右侧自动出现审阅侧栏（锚定文字 + 作者 + 时间 + 内容 + 回复），点条目会在正文里
高亮对应锚点并滚动过去；没有批注时侧栏不占位。

## 文件模板与双页并排

**文件模板**（`DOC_TEMPLATES`）把**样式与页边距绑成一体** —— 公文体例里页边距本身就是格式的一部分，
让人分别选「样式」和「页边距」只会拼出既不是甲模板也不是乙模板的东西。demo 顶栏的那个下拉就是它：

| key | 名称 | 样式 | 页边距 |
| --- | --- | --- | --- |
| `manager` | 管理人文件 | 规格表默认那套 | 四边 25mm |
| `govDoc` | 简易公文格式 | **同一套**（用户已定：两套只差页边距） | 上 37 / 下 35 / 左 28 / 右 26 mm |

模板的类型是「整份 spec 的 `DeepPartial`」而不是「只有页边距」，所以将来真要给第二套不同的字体字号，
往 `spec.styles` 里加就行，预览 CSS 与 docx 样式都从 `resolveSpec(template.spec)` 派生，不用改结构。
`MARGIN_PRESETS` 仍保留（它是已发布的 lib 接口），但已改为**由 `DOC_TEMPLATES` 派生**，不另存一份边距字面量。

切模板时组件会**清掉量测缓存并整篇重量**（`clearMeasureCache` → `refreshLayout({ force: true })`）：
页边距一变版心就变，`render/measure.ts` 里所有行数与行高全部失效，不清缓存就会拿旧版心的量测值算页码。
重量期间插入符与选区按「块 id + 字符偏移」还回去，不会丢。

**双页并排**是自适应的：页带是 `flex-wrap` 横排（`lib/render/css.ts` 的 `.{ns}-pages`），容器够宽两页一排、
不够自动回落成一页一排；`.{ns}-page` 是 `flex: none`，宁可让外层横向滚动也不压窄纸宽 ——
纸一窄版心就变，实测行盒与分页算术会立刻脱节。页间那枚换页标记自己占满整行（`flex-basis: 100%`），
否则并排时会被挤到两页之间去。打印不受影响：`@media print` 里把页带改回 `display: block`，仍是一页一张纸。

demo 的样本文档长度是刻意留够的：两套模板的版心高差 22mm（≈ 2.5 行），样本又正好跨在分页边界上，
所以切模板一定看得见页数变化（否则「切模板必须整篇重量」这条断言无从观察）。

## 编辑层

`editable` 打开后，`.wtp-content`（分页后的每一页版心）就是一个 contenteditable，
用户写的是类 docx 的版面，不需要接触任何 md 语法。

分工是明确的：**DOM 是手感的真相，模型是导出的真相**。

- 打字、输入法组字、选区、原生剪贴板都留给浏览器，手感是原生的；每次 `input` 再把 DOM 读回模型；
- 结构性操作（回车分段、退格合并、工具栏加粗／下划线／改色、`alt+4` 金额格式、插入特殊空格、加批注）
  直接改模型，再重排渲染 —— 因此界面上改的和导出 docx 用的永远是同一份模型，
  不会出现「界面改了、导出没改」。

**正常输入不得触发重排**（否则每敲一个字就重建 DOM、丢掉插入符）这条约束靠两点落实：

1. 渲染只读 `viewDoc` / `pages` 这两个浅响应式快照，编辑中的模型不参与渲染，
   所以打字不会让 Vue 重新渲染 —— `lib/edit/dom.ts` 的坐标换算和 `render/measure.ts`
   的增量缓存都只是读 DOM，不动 DOM；
2. 每次 `input` 仍然量测一遍（只重量内容变过的那块），只有当分页结果确实变了
   （行数或行边界变了）才更新快照、重建 DOM，再按「块 id + 字符偏移」把插入符放回去。
   分页没变时 DOM 原样不动，插入符天然还在原处。

几个具体的约定：

- **自动编号不是模型内容**。段首的「一、」包在 `contenteditable="false"` 的 `.wtp-num` 里，
  不可编辑也不参与读回；页面上、docx 里都是同一个编号来源（`numbering.ts`）。
- **回车分段**：在落点切开当前段落；若当前是标题类段落，后半段成为正文段
  （公文习惯：标题一行一段，回车后就该写正文）。
- **退格合并**：仅当插入符在段落最前面且没有选区时接管，合并到上一段并删除本段。
- **修订模式**：新增文字标 `w:ins`；删除不真删，把删掉的文字原地补回来标 `w:del`，
  与 Word 开着修订时看到的一致。读回靠「和模型比一遍」求出被改动的区间。
- **批注**：选中文字后写内容即可；焦点离开正文（点进批注输入框）时靠选区快照记住锚定范围。
- **粘贴**按纯文本处理，换行还原成新段落（不导入外部 HTML 的样式）。

### 快捷键

快捷键只在焦点位于 A4 版面（`.wtp-content`）里时生效，且都会 `preventDefault`，不触发浏览器默认行为。

| 快捷键 | 作用 |
| --- | --- |
| `ctrl+B` | 切换选中文本的加粗 |
| `ctrl+U` | 切换选中文本的下划线（模型里是 `underline`，docx 里是 `<w:u w:val="single"/>`） |
| `ctrl+shift+E` | 切换修订模式（组件只 `emit('toggle-track-changes')`，由调用方翻转 `trackChanges`） |
| `alt+4` | 把选中的数字改写成 `#,#00.00` 格式（如 `12345.6` → `12,345.60`）；解析不了就 `emit('toast')` 且不改模型 |
| `ctrl+Z` / `ctrl+Y` | 撤销／重做 |
| `ctrl+F` / `ctrl+G` | 打开查找替换面板（`emit('open-search', …)`，面板由调用方画），分别聚焦查找框／替换框 |
| `Enter` / `Tab` | 回车分段（接管）；Tab 不把焦点跳出去 |
| `ctrl+P` | 不接管 —— 浏览器自己的打印 |

`alt+4` 的解析与格式化是纯函数（`lib/edit/amount.ts` 的 `formatAmount`）：接受可选负号、千分位逗号、
一个小数点，输出固定两位小数（第三位起四舍五入）。刻意不用 `toLocaleString` —— 它按运行环境的 locale
选分组符与小数点，同一段文字在不同机器上会输出不同结果。

### 插入特殊空格

工具栏的「插入」下拉可以往插入符处插入三种不会被 HTML 折叠的空格：`EM SPACE (U+2003)` 全宽、
`EN SPACE (U+2002)` 半宽、`FOUR-PER-EM SPACE (U+2005)` 四分之一宽。有选区时替换选区，
插入后插入符落在刚插入的空格之后；下拉选完自动复位回占位项（否则再选同一项不会再触发 `change`）。
它们进 docx 就是普通文本字符，不需要特殊处理。

### 打印

`ctrl+P` 交给浏览器，但打印样式（`@media print`）会把编辑器外壳（顶栏、样式库、工具栏、源码 pane、
语法说明、批注侧栏、页间换页标记）全部隐藏，只留下 A4 纸。纸张尺寸取自规格表（`@page` 的 `size`），
`margin` 归 0 —— 纸上的白边由纸张自己的 padding（= 页边距）提供，页盒再留一次就成了双份。
分页靠每张纸自己的 `break-before: page`（第一张除外），所以打印预览里页数、断页位置与版面一致，
既不会被裁掉后面几页，也不会多出空白页。

打印样式分两处：组件自己的 `.wtp-*` 规则在 `lib/render/css.ts` 注入的那份 CSS 里（要带 `!important`，
SFC 的 scoped 样式加了 `data-v` 属性，特异性更高）；App 外壳的规则在 `src/App.vue` 的 `@media print` 里。

### 查找替换与导航窗格

`ctrl+F` / `ctrl+G` 打开的是同一个**浮动小面板**：浮在预览区右上角、拖标题栏可移动（拖不出窗格范围）、
`Esc` 或 `×` 关闭，关闭时把焦点还给版面。两种入口只是让焦点分别落在查找框／替换框。
面板里有查找框、替换框、「第 n / 共 m 处」计数（无命中时「共 0 处」）、上一个／下一个／替换／全部替换、
`使用正则表达式` 复选框（默认不勾）与范围单选（`全文` 默认 / `当前选中的文本`）。
面板位置与开关由 App 持有，匹配与高亮由组件持有。

- **匹配是纯函数**（`lib/edit/search.ts`，可在 node 里单测）：跑在每个块的「可搜索文字」上，
  批注锚点与格式切换都不占字符、不会漏匹配；正则模式用 `new RegExp(query, 'g')`，
  非法正则交给 `validateQuery` 出提示文案，`findMatches` 一律返回 `[]` 而不抛异常。
- **范围**在面板打开的那一刻用 `getSelectionScope()` 捕获（焦点一进输入框，实时选区就没了）。
  匹配必须完整落在某一个区间内，不许跨区间。
- **高亮用 CSS Custom Highlight API**（`lib/render/css.ts` 的 `SEARCH_HIGHLIGHT` / `SEARCH_CURRENT_HIGHLIGHT`），
  一个 DOM 节点都不动，所以查找不会触发重排。一个匹配可能横跨两页（同一块被切开），
  高亮会**按分页片段切成多个子 Range** —— 用「起点在前一页、终点在后一页」的单个 Range
  会把两页之间的换页标记与页脚一并圈进去。浏览器不支持时降级成「没有高亮」，匹配数、跳转、替换照常。
- **替换落到模型**：普通模式真删真插（`replaceRange`），修订模式下是「把旧文字标成 `w:del` + 插入新文字标
  `w:ins`」，与手输一样进撤销栈、一样会导出到 docx。替换结果继承被替换区间内第一个 text 片段的
  加粗／下划线／颜色，不会把一段加粗文字换掉却静默丢格式。
- **导航窗格**挂在编辑器最左侧（固定 `200px`，文档有标题时自动出现、可折叠），条目是 `h1`/`h2`/`h3`
  （`title` 不进，与 Word 的导航窗格一致），显示「自动编号 + 块内纯文字」，按层级缩进；
  点击会把该块滚到可视区中间，可编辑时再把插入符放到自动编号之后。
  大纲取自**渲染快照**（`viewDoc` / `viewNumbering`）、只在指纹（`outlineSignature`）变化时才发事件，
  因此正文打字不会带着左栏重渲染。

已知取舍：

- 撤销栈是组件自己按「一次编辑一步」记的（深度 200），不接浏览器原生撤销，
  因此和系统菜单里的「撤销」不是同一套；
- 跨段落的选中删除由浏览器处理，结果是各段各自删掉选中的文字，**不等于** Word 的「合并成一段」；
- **软换行目前只在表格单元格内支持**（`:::table` 围栏里的 `{br}`，导出为 `<w:br/>`），
  普通段落是否推广待定；格内 **Enter 不接管**、**Shift+Enter 插软换行**（插入符落到换行之后），
  格首 Backspace 与格尾 Delete 被拦下不让浏览器并格；
- **表格结构操作只在「一张表」内部与「删掉整张表」两件事上**：增删行列、表头行／附注行开关、行高两档
  都落在 `lib/edit/table.ts` 的纯函数上；删整表是工具条最右的显式按钮（`removeTable`，**不二次确认**，
  靠撤销兜底）。增删行列会让 `cellId` 里的行/列下标整体位移，所以操作后的插入符按新下标重算
  —— 旧 id 一律作废；
- **`↑` / `↓` 跨格靠 DOM 量测**（比较插入符与格内首/末字符的 `top`）：判不准就不接管，所以多行格、
  量测退化的场合就是「不跨」；落点也不保留横向位置。这部分**只有推理、没有浏览器实测**；
- **删表后的插入符落点**优先取被删表之前第一个段落的末尾，其次之后第一个段落的开头；两边都没有
  可落点的段落时传 `undefined`，靠 `refreshLayout` 的兜底（这种文档形态没被浏览器实测）；
- **格内换样式会改行高、因此页数可以变**（预期行为）；两组对齐不改行高、不改换行点，因而不改页数；
- **关掉修订模式后在「刚被标成插入修订」的文字后面继续打字**，新字会并进那个 `w:ins` 区间
  （读回时按 DOM 上下文继承格式，浏览器就是把字插进了那个 `<span>` 里）。
  在别的段落里打字不受影响 —— 这是「DOM 是手感的真相」付的代价，没有做逐字 diff；
- 源码视图（类 md）与编辑层之间来回切换会经过一次序列化，修订的作者／时间戳与批注的
  回复关系在那条路上会丢（md 语法里没有这两个位置）——只做展示用，别拿它当存档。
- **查找替换**：替换文字按纯文本处理，**不支持 `$1` 这类反向引用**；**默认大小写敏感**，
  不提供「忽略大小写」开关；正则的零宽匹配（如 `^`、`a*`）不进结果集，只会被跳过去
  —— 否则每一处空匹配都会变成一条「第 n 处」，`全部替换` 也会在每个字符位置插一次。
- **已标记删除（`w:del`）的文字不参与查找与替换**。修订模式下「替换」是「把旧文字标成删除 + 插入新文字」，
  旧文字仍留在模型里；若查找还命中它，对同一处反复替换就会不断叠加插入，跳过才能收敛。
- **导航窗格的大纲取自渲染快照**：刚敲进去、还没触发重排的标题文字，要等下一次分页才会反映到左栏
  （换来的是「正文打字不带着左栏重渲染」）。


## 源码语法

一个非空行就是一段（**行与行不会合并成同一段** —— 公文写作习惯是一行一段，用空行分隔反而要多敲回车）。
空行只起分隔作用，不产出内容。

| 行首标记 | 含义 |
| --- | --- |
| `# 标题` | 文本标题（华文中宋 18pt 加粗居中） |
| `## 标题` | 一级标题，自动编号 `一、` |
| `### 标题` | 二级标题，自动编号 `（一）` |
| `#### 标题` | 三级标题，自动编号 `1、` |
| `@ 抬头` | 抬头（正文但取消首行缩进） |
| `>> 落款` | 落款（正文但右对齐），连续多行成组 |
| `- 条目` | 列表段落（五号 10.5pt，无段前段后） |
| `! 条目` | 列表标题（五号加粗居中） |
| `---`（独占一行） | 分节符：新起一页，页码从 1 重排 |
| `===`（独占一行） | 分页符：只强制换页，页码连续 |
| `:::table … :::` | 表格围栏块，见下 |

### 表格

表格用一段围栏块包起来，首行是 `:::table`（可带 `minLines=1|2`、`cantSplit=yes|no` 两个参数，
只写非默认值：`minLines` 默认 1、`cantSplit` 默认 true），末行是独占一行的 `:::`：

```
:::table minLines=2
> 单位：元
| 项目 | 金额 |
| 甲 | 1,234.00 |
< 注：以上金额不含税
:::
```

- `>` 开头是 **unit 行**（表头行上方的「单位：元」这类文字）、`<` 开头是 **note 行**（表尾附注），
  两者**整行一格**、无边框，分别右对齐／左对齐（附注还顶端对齐）；`|` 开头是 **body 行**。
- 表内每行**按未被转义的 `|` 切格**，所以格子里要有竖线就写 `\|`，要有反斜杠就写 `\\`；
  每格的文字走同一套行内语法（`**加粗**`、`__下划线__`、`{红|…}`、`{+…}`、`{-…}`、`[[…|批注]]`）。
- **行高**两档就是 `minLines`：1 = 最小一行、2 = 最小两行（导出为 `HeightRule.ATLEAST`，
  值 = minLines × **该行各格样式的最大行高**）；`cantSplit` 默认禁止本行跨页断开（Word 的 `w:cantSplit`）。
- 表格总宽固定占满版心宽（页面宽 − 左右页边距），列宽等分、除不尽的余数给最后一列。
- 其它行首（空行等）一律忽略；一张表连一行内容都没有时规范化为「1 行 1 个空 body 格」。
- **格首指令**：一格的内容可以整格包在 `{@<token>[,<token>]…|<格内正文>}` 里，用来逐格换样式与两组对齐
  （unit / note 行也认）。token 三族互不冲突、不认识的 token 一律忽略：样式名（`title`/`h1`/`h2`/`h3`/`body`/
  `salutation`/`signature`/`attachment`/`listTitle`/`listItem`，缺省 `listItem`）、水平（`left`/`center`/`right`，
  只做这三档、不提供两端对齐）、垂直（`top`/`middle`/`bottom`，缺省 `top`）。
  序列化顺序固定 `kind` → `h` → `v`，且只写非默认值 —— 三个都没值的格不写指令，老样本一个字节不变。
  正文里真写 `{@h2|x}` 会被转义成 `\{@h2\|x\}`（反斜杠吃掉 `{`），往返可逆；不合法的形式
  （`{@` 找不到闭合的 `}`、或没有分隔 token 与正文的 `|`）一律当普通内容处理，绝不吞掉后面的内容。
  这一族只在表格解析里认，普通段落里没有这套语义，也不与 `{+ins}` / `{-del}` / `{#RRGGBB|…}` / `{br}` 冲突。
  例：`> {@h2,right|单位：元}`、`| {@h2,center|项目} | {@center|金额} |`、`| {@left,bottom|1,234.00} |`。

表格在预览里按**行**排出来：外层 `<table>` 铺满版心（固定布局、合并边框），格内文字缺省是「列表段落」样式、
换成别的样式时用那条样式自己的字体字号与行距，单元格左右内边距与 docx 侧取同一个数（108 缇 = 5.4pt）。
行高的最小值落在格内 div 的 `min-height` 上、按该格样式算 —— 一行里各格取各自的值，实际行高天然由最高的那格决定
（docx 侧的 `w:trHeight` 用同一条规则）。分页时表格**行是原子的**：一行放不下就整行挪到
下一页，行内不拆；同一页相邻的同表行合并成一个片段（一页一张 `<table>`），跨页才断开。
demo 的工具栏有「插入表格」按钮：点开是一个浮动规格面板（与查找替换面板同一套做法，可拖、
`×`／`Esc` 关），在里面选**行数**与**列数**再插入，默认 2 行 × 3 列、最小行高两行、禁止跨页断行。
面板里敲进去的数值不设信任：越界会夹到 1–30 行 / 1–12 列，输入框清空则按 1 处理。

**表格编辑交互**（W4b-1）：光标落进任何一个格子时，主工具栏**下方**会出现一条**表格上下文工具条**
（跟着 `selection-change` 事件里的 `selection.table` 走，落点不在格内就整条消失），上面是：
落点提示（`第 N 行第 M 列`，行列都是下标、显示时 +1；表头行／附注行没有列的概念，只显示行名）、
行（`上方插入行`／`下方插入行`／`删除行`）、列（`左侧插入列`／`右侧插入列`／`删除列`）、
行高两档 radio（`最小一行`＝1 / `最小两行`＝2，即 docx 的 `HeightRule.ATLEAST` 倍数）、
以及表头行与附注行的有／无 radio。按钮与 radio 一律 `@mousedown.prevent`，焦点不离开正文，
落点与原生选区才保得住。禁用规则：`删除行` 在光标不在正文行、或正文行只剩一行时禁用；
`删除列` 在只剩一列时禁用。`cellId` 里嵌的是行/列下标（`tb1.r2c1`），任何增删都会让其后的
格子 id 整体位移，所以操作完的插入符是按**新下标**重算后放回去的（偏移再夹到该格当前长度以内）。

**表格收尾**（W4b-2）在工具条右侧又加了**水平**（左／居中／右）与**垂直**（顶端／居中／底端）两组对齐按钮，
以及最右端的**「删除表格」**（**不二次确认**，靠 `pushHistory` 的撤销兜底 —— 与全仓库一致，项目里没有弹窗形态）。
两组对齐都是**逐格**的：给 `TableCellModel.align` 存 `{ h?, v? }`，只存被改过的那一维；
按钮的 active 态吃**已解析默认值**后的实际值（水平：unit 右 / note 左 / body 跟该格样式；垂直一律顶端），
**再点同一个值就是清除覆盖、回默认**。水平只做三档，不提供两端对齐；对齐不改行高、不改换行点，所以**不改页数**。
格内**换样式**走主工具栏上方那条样式 chip 行：光标在格内时它作用于**该格**（`TableCellModel.kind`，缺省「列表段落」），
只有那一格的类名从 `wtp-listItem` 变成 `wtp-<kind>`；**换样式会改行高，因此页数可以变**，这是预期行为。

**键盘跨格**：`Tab` / `Shift+Tab` 在格内按**行优先**顺序跨格（unit / note 行整行算一格、渲染时补出来的幻影格跳过）；
**在最后一格按 Tab（或第一格按 Shift+Tab）不作任何响应** —— 不换行、不自动加行、不把焦点跳出正文。
`←` / `→` 只在**格首**（←）或**格尾**（→）跨到上一格末尾 / 下一格开头，格内其它位置仍由浏览器移动光标。
`↑` / `↓` 只在插入符位于该格的**首 / 末视觉行**时跨到上下相邻格（同列；目标是 unit / note 行时列归 0），
判定靠 `getClientRects()` 比较插入符与格内首 / 末字符的 `top`：**判不准就完全不接管**（fail-open），
落点一律是目标格开头、不保留横向位置。跨格只挪原生选区、**不改模型、不重排**（所以插入符不会丢、也不会触发重排）。

格内**可以直接打字**：格子是编辑层里的「伪块」，id 用 `cellId(tableId, r, c)` 挂在格内那层 div 上，
于是坐标换算一行都不用改；加粗／下划线／改色、查找替换、批注也都覆盖格内文字。
**Shift+Enter** 在格内插一枚**软换行**（`{br}`，零宽），插入符落到换行**之后**
（软换行零宽，默认的坐标还原会落到换行之前 —— 那会让回车后敲的字打回上一行）；
格内 **Enter 不接管**（单元格是单段落，分段表达不出来）。**格首 Backspace 与格尾 Delete 会被拦住**：
放给浏览器的话原生会把相邻 `<td>` 的 DOM 并掉，表格结构当场就坏。
格内多行粘贴会把换行变成软换行 `{br}`（同上，单元格是单段落）。

行内标记（可互相嵌套）：

| 写法 | 含义 |
| --- | --- |
| `**文字**` | 加粗 |
| `__文字__` | 下划线（导出为 `<w:u w:val="single"/>`） |
| `{红｜文字}` | 改色，支持中文色名（红黑蓝绿紫橙灰黄白）或 `{#RRGGBB｜文字}` |
| `{+文字}` | 插入修订（导出为 `w:ins`） |
| `{-文字}` | 删除修订（导出为 `w:del`） |
| `[[文字｜批注内容]]` | 批注，锚定在「文字」上 |
| `{br}` | 软换行（Word 的 `<w:br/>`）：零宽、不占字符位 |
| `\` | 转义上述标记字符 |

> 上表里的全角竖线是为了在文档里显示清楚，实际语法用的是**半角 `|`**。

## 样式规格表

规格表在 [`src/lib/spec.ts`](src/lib/spec.ts)，是预览 CSS 与 docx 样式的**唯一来源**，
`resolveSpec(override)` 做逐层合并。默认值：

| 类型 | 字体（中文／西文） | 字号 | 加粗 | 对齐 | 首行缩进 | 行距 | 段前／段后 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 文本标题 | 华文中宋／Times New Roman | 18pt | ✓ | 居中 | — | 26pt 固定值 | 1.5 行／1.5 行 |
| 一~三级标题 | 仿宋／Times New Roman | 14pt | ✓ | 两端 | 2 字符 | 25pt 固定值 | 0.5 行／0.5 行 |
| 正文 | 仿宋／Times New Roman | 14pt | — | 两端 | 2 字符 | 25pt 固定值 | 0.5 行／0.5 行 |
| 抬头 | 仿宋／Times New Roman | 14pt | — | 左 | — | 25pt 固定值 | 0.5 行／0.5 行 |
| 落款 | 仿宋／Times New Roman | 14pt | — | 右 | — | 25pt 固定值 | 0.5 行／0.5 行 |
| 列表标题 | 仿宋／Times New Roman | 10.5pt | ✓ | 居中 | — | 12pt 最小值 | 0／0 |
| 列表段落 | 仿宋／Times New Roman | 10.5pt | — | 两端 | — | 12pt 最小值 | 0／0 |

- 页面默认 A4，四边 25mm（= 「管理人文件」模板的页边距）。文件模板见上一节：`DOC_TEMPLATES` 把样式与
  页边距绑成一体，`MARGIN_PRESETS` 由它派生（四边各自取值）；`page.margin` 也可以直接覆盖。
  页码段落用内置「页脚」样式（居中 9pt）。
- 样式名对照：

| 块 | docx 样式名 | 来源 |
| --- | --- | --- |
| `title` | 标题 | Word 内置（Title） |
| `h1` / `h2` / `h3` | 标题 1 / 标题 2 / 标题 3 | Word 内置（Heading 1-3），自动带上大纲级别 |
| `body` | 正文 | Word 内置（Normal）。正文段落不挂样式，格式定义在默认样式上 |
| `listItem` | 列表段落 | Word 内置（List Paragraph） |
| `footer` | 页脚 | Word 内置（Footer） |
| `salutation` / `signature` / `listTitle` | 抬头 / 落款 / 列表标题 | 自定义（Word 无对应内置） |

- **「内置」的判定依据是 `w:name` 与 Word 的本地化名逐字相等**（含「标题 1」中间那个空格），
  不是 `w:styleId`。所以样式 id 仍保留 `WT-` 前缀 —— 既不影响内置归属，又能避开 `docx` 库的坑：
  styleId 一旦撞上它的内置样式表（`Heading1`、`Title`），它会额外注入一份自己的默认定义，
  同一份 `styles.xml` 里就会出现两个同 id 的 `w:style`。**反向解析按样式名匹配。**
- 命中内置样式后 Word 会自动补上大纲级别，标题因此能出现在导航窗格里，这是改内置名顺带拿到的。

## 架构

```
src/lib/
  spec.ts            页面与样式的唯一真相源 + 文件模板 DOC_TEMPLATES + 单位换算
  types.ts           文档模型（块 / 行内 / 修订 / 批注）+ 批注锚定文字提取
  numbering.ts       中文序数编号与层级重置
  md/parse.ts        类 md → 模型        md/serialize.ts  模型 → 类 md
  edit/model.ts      编辑操作的纯函数层（切分／合并／替换／格式化／批注／修订）
  edit/dom.ts        预览 DOM ⇄ 模型的桥（读回 inline、插入符与选区的坐标换算）
  edit/amount.ts     金额格式化（千分位 + 两位小数，纯函数，不碰 locale）
  edit/search.ts     查找与替换（纯函数：字面量／正则、范围限定、跳过删除修订、替换留痕）
  edit/outline.ts    导航窗格的大纲（h1/h2/h3 → 条目 + 指纹）
  docx/export.ts     模型 → docx（段落样式、页码域、w:ins/w:del、w:u、批注）
  render/css.ts      规格表 → 预览 CSS（含打印样式）
  render/html.ts     行内标记 → HTML（预览、量测、编辑读回共用同一套结构）
  render/measure.ts  DOM 实测：行数、行高、每行起始字符偏移（带增量缓存）
  render/paginate.ts 纯函数分页：装箱 + 跨页按行切开 + 分节重编号
src/components/WordPaper.vue   预览 + 编辑组件 + 批注审阅侧栏
scripts/                       验收脚本（见下）
```

分页不是 CSS 断页，而是「实测行盒 → 装箱 → 在行边界切开」算出来的：行距是固定值，
行高因此是确定量，分页可以算出来而不是猜。孤行控制默认开启（页尾与页首各至少 2 行，
因此少于 4 行的段落不会被拆开）。

## 验收方式

| 命令 | 验的是什么 |

## 已知限制

- **字体依赖本机安装**。预览用 `仿宋／华文中宋／Times New Roman`，docx 里写的也是这几个名字。
  这三个都是商业字体，不能内置；换一台没装这些字体的机器，预览会回退到 serif，行宽会变。
- **「段前／段后 N 行」用磅值写死**。`docx` 库没有暴露 Word 的 `w:beforeLines`（按行计的动态段距），
  这里按本段行距换算成固定磅值。视觉等价，但不是随行距联动的动态值。
- **自动编号写成了正文文字**，不是 Word 原生多级列表。好处是预览所见即所得、重新导入能准确还原；
  代价是在 Word 里手动增删标题不会自动重编号（在本组件内会自动重排）。
- **分节符会多出一个空段落**。`docx` 库用一个只带 `w:sectPr` 的空段落承载分节符，
  Word 把它读成含分页符的一段，效果是上一节末尾多一个空行。
- **批注的「已解决」状态需要线程**。`docx` 只在存在 `parentId` 回复时才会写
  `commentsExtended.xml`，因此单条批注标记 `resolved` 不会生效（库的现状，非本项目取舍）。
- 预览里的批注高亮与修订着色是**近似**，不追求与 Word 像素级一致。
- 预览分页与 Word 分页在同样规则下目前完全一致（见 `verify:pages`），但两者毕竟是不同的排版引擎，
  换字体、混排西文比例很高、或出现超大表格时仍可能出现逐行差异。
- **表格的预览版式没有本机浏览器实测**（2026-09-13 起本机 Edge 的程序化启动坏了，见 `PLAN.md` 第 9 节第 7 条）。
  行高最小值靠格内 div 的 `min-height`（表格行不吃 `<tr>` 的 `min-height`），
  单元格左右内边距与 docx 侧取同一个数（108 缇 = 5.4pt）；另有一处已知偏差：
  列表段落的 CSS `line-height` 是固定 12pt，而 Word 的 `atLeast 12pt` 是「不小于」，
  单行格两者相同（`minLines=2` → 24pt），**多行格**可能差零点几磅。
- **横竖混排的打印同样没有本机浏览器实测**（同上）。屏幕上的每页几何（纸宽高、页边距、方向）由
  行内样式给出、可断言；打印时的方向靠两档命名 `@page`（`wtp-portrait` / `wtp-landscape`）表达
  —— 命名页与 `break-before: page` 合用在本机只能断言到 `@page` 规则与断页属性，真打一份混排 PDF
  的观感需要换一台 Edge 可用的机器复核。
- 编辑层的取舍见上文「编辑层 · 已知取舍」；其中「跨段落选中删除不合并段落」是当前最明显的一处
  与 Word 的差异。
